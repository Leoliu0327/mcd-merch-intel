# 麦当劳 MCP 工具参考（周边情报场景）

调用前用 `ToolSearch` 加载 `mcp__mcd-mcp__*` 的工具 schema，再按本文做字段映射。

## 1. 源 A：活动日历 `mcp__mcd-mcp__campaign-calendar`

**定位**：时效校验主源。回答"什么时候开始 / 什么时候结束 / 现在还能不能拿到"必须以此为准。

| 项目 | 说明 |
|---|---|
| 参数 | `specifiedDate`（可选，yyyy-MM-dd）。传入时以该日为锚点返回当天 + 时间线前后各一个邻近活动日（共三天）；不传返回当月全部活动 |
| 返回 | **按日期分组的非结构化 Markdown 文本**，日期后带"往期回顾 / 今日"标签；每条活动含「活动标题」「活动内容介绍」「活动图片介绍」 |
| 调用策略 | 用户未指定时间 → 不传参，拿整月；用户问"X 月有什么玩具"→ 传该月某日（如 `2026-10-01`）后按需再补一次不传参的整月查询 |

⚠️ **实测要点（重要）**：本工具**不返回结构化的 `beginTime / endTime / activityStatusText` 字段**。
时间信息散落在「活动内容介绍」文案里（形如"10月8日10:45开售""10月8日至10月21日"），需自行从文案中提取。
活动段落上的"往期回顾"标签**不等于**活动已结束——它只表示该日期早于今天，同一活动常在多日重复出现。
**没有明确结束时间的活动，结束时间一律写「官方未公开」，禁止用活动的最后出现日期倒推为结束时间。**

**字段映射 → 输出模块**

| MCP 信息 | 落到 |
|---|---|
| 活动标题 | 【周边名称】的关联活动（周边名优先取源 B 的商品名） |
| 文案中提取的开售时间 | 【活动时效】开始时间 |
| 文案中提取的截止时间（多为缺失） | 【活动时效】结束时间，缺失写「官方未公开」 |
| 日期分组标签 + 文案时间 | 【活动时效】状态：即将上线｜进行中｜已结束 |

**状态归一化**（无状态字段，全部自算）：
- 文案开售时间晚于当前时间 → `即将上线`
- 开售时间已过、且无结束时间或结束时间未到 → `进行中`
- 明确写了结束时间且已过 → `已结束`
- 完全无法判定 → 状态写 `官方未公开`，**不得默认"进行中"**

**关键词匹配**：用周边名 / 联名 IP 名 / 艺人名在「活动标题」与「活动内容介绍」全文做模糊匹配。
麦当劳艺人联名的标题格式通常是「麦当劳 X <品牌/IP>」或「麦当劳联动<艺人名>」，匹配时要把艺人名与品牌名都试一遍。

## 2. 源 B：积分商城周边 `mcp__mcd-mcp__mall-points-products`

**定位**：周边本体主源。回答"是什么 / 什么款式 / 要多少积分 / 是否限量"。

| 项目 | 说明 |
|---|---|
| 参数 | `catRuleIds`，逗号分隔多选 |
| 周边相关取值 | `2>8` 周边产品；`2` 实物商品 |
| 建议传参 | `2>8,2`（周边场景默认）；用户只要纯周边 → `2>8` |
| 非周边类目 | `1>4` 商品券、`2>9` 实物礼品卡、`1>6>20/21/22/25/34/40` 各类派对与体验活动 —— 周边情报场景**不要**传这些 |

**实测返回字段**（JSON，非 Markdown）：`spuName`、`spuId`、`point`（所需积分）、`selling`（卖点，限量规则常写在这里）、`upTime`（兑换起始）、`downTime`（兑换截止）、`spuImage`、`catName`、`status`、`price`、`shopId`。

- `status`：1-仓库中 / 2-上架 / 3-售罄 / 4-下架 / 5-预热
- `catName` 实测值包含「玩具」「鞋袜」等，`2>8,2` 过滤后也可能出现「到店专用」券类，需按 `catName` 二次筛选
- 限量 / 每日限量 / 限购规则**藏在 `selling` 文案里**，必须逐条读 `selling` 提取，不能只看字段
- ⚠️ 该商城是**积分兑换渠道，不含门店套餐赠品类周边**。用户问的是套餐赠品 / 门店加价购周边时，本源大概率查不到，此时以源 A 为唯一依据

**尽调要求**：关键词在 `2>8,2` 下无命中时，**必须再补一次不带 `catRuleIds` 的全量查询**确认，避免漏掉类目归类异常的商品，之后才能判兜底。

拿到 `spuId` 后调用 `mcp__mcd-mcp__mall-product-detail` 取 SKU 级详情。

## 3. 源 B 补充：商品详情 `mcp__mcd-mcp__mall-product-detail`

| 项目 | 说明 |
|---|---|
| 参数 | `spuId`（必填，来自上一步） |
| 用途 | 拆款式（SKU 列表）、判是否随机、取兑换限制与库存标记、取 `shopId` |

**字段映射 → 输出模块**

| MCP 信息 | 落到 |
|---|---|
| 商品名 / SPU 名 | 【周边名称】 |
| SKU 列表（多款式） | 【核心亮点】+【获取规则】的"是否随机" |
| 所需积分 / 兑换门槛 | 【获取规则】套餐门槛 |
| 库存 / 限量标记 | 【获取规则】是否限量 +【注意事项】⚠️ |
| 门店相关字段 | 【注意事项】门店库存差异 |

**是否随机的判定口径**
- SKU 多款且下单只需选 `spuCategory` 不指定具体款式 → `随机发放`
- SKU 可由用户明确选择 → `可选款式`
- MCP 未给出款式信息 → `官方未说明`

## 4. 补充源（按需）

| 工具 | 触发条件 | 取数 |
|---|---|---|
| `mcp__mcd-mcp__query-lottery-info` | 用户问"抽奖能抽到什么玩具/周边" | `activityStatusText`、`beginTime/endTime`、`prizes[]` |
| `mcp__mcd-mcp__available-coupons` | 券列表出现玩具兑换券 | 券名称、状态、促销标签 |

补充源只用于补齐 `【获取规则】` 与 `【核心亮点】`，**不用于**推翻源 A 的时效结论。

## 5. 清洗规则

剔除以下内容后组装：

1. **官方冗余话术**：品牌 slogan、活动宣传语、"快来参与"类引导、重复出现在标题与副标题的同一句
2. **过期活动**：状态为已结束的条目，不展示任何可兑换描述
3. **重复字段**：同一周边在源 A / 源 B 重复出现时合并为一条，保留字段更全的一侧
4. **无关条目**：源 A 里与周边无关的纯餐饮优惠活动
5. **空字段**：值为空 / null / "-" 的字段不输出，对应模块位置写「官方未公开」
6. **价格与渠道**：涉及二手价、代购价的字段一律丢弃

## 6. 双源冲突处理

| 冲突 | 处理 |
|---|---|
| 源 A 有活动、源 B 无商品 | 只输出活动层信息，`【获取规则】`写「官方未公开具体兑换规则」 |
| 源 B 有商品、源 A 无匹配活动 | 时效写「活动日历未匹配到对应活动，时效以商品页为准」，并加 ⚠️ 提示以门店实际为准 |
| 两源时效不一致 | 以源 A（活动日历）状态字段为准，另标注差异 |
| 两源都无数据 | 触发兜底：`当前暂无该麦当劳周边的官方情报信息，可关注官方最新活动更新` |
